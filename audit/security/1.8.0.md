## Scanner-visible but safe

- `class-admin.php` "Read full review": `wp_kses_post( wpautop( esc_html( $content ) ) )` - escaped first; wpautop only adds p/br.
- `class-admin.php` claim proof disclosure: `nl2br( esc_html( ... ) )`.
- `class-template-helpers.php` criteria renderer: label via `esc_html`, rating an int clamped to 1-5.
- `Admin::moderate_review()` dispatches via `rest_do_request()`: the route permission callbacks run; the GET action links are nonce + `moderate_listora_reviews` checked.
- `Claim_Proofs::download()` `readfile`: nonce + `manage_listora_claims`/`manage_listora_settings` + `_listora_claim_proof` meta check; nosniff + CSP headers.
- `Claim_Proofs::run_health_test()` `wp_remote_get`: fixed own-uploads URL, no input - no SSRF.
- Interpolated SQL in the dashboard controller, `wb_listora_count_user_listings`, `Space_Listings_Model`, analytics-lite: only table names from `$wpdb`/constants and `%s`/`%d` placeholder lists from `array_fill`. No request data.
- Search-engine seams (`wb_listora_search_where_clauses`, `_where_params`, `_orderby`) take raw SQL fragments by design; only code can hook them.
- Setup wizard `listora_wizard_skip`: capability + `wp_verify_nonce`.
- `POST /listings/bulk` is public on purpose (read-many by id); non-public listings are filtered out (verified above).
