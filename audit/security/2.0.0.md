# Security review - WB Listora 2.0.0 (Free), 2026-10-12

Scope: `git diff v1.9.0..HEAD` on branch 2.0.0, own code only (vendor/, libs/, build/ sources reviewed via src/, node_modules/, tests/, languages/, docs/, bin/ excluded). 219 PHP files, +13.1k/-12.2k. Combo install (Pro active), listora.local.

Gate E tooling and the G2 enforced RouteAuthorityTest are still not adopted in this repo; the matrix is runtime spot checks plus regression tests, per the 1.9.0 precedent.

## Scanner-visible but safe

- Leads: scoped to `owner_id = get_current_user_id()` behind login; item permission refuses uid <= 0.
- Services: `can_manage_listing()` checks login before comparing `post_author`.
- Claims: proofs pass `wp_check_filetype_and_ext`, random names, private dir, served through admin-post with nonce + capability + proof meta check.
- Listings owner actions use `require_listing_owner` (login + author/cap); `rest_pre_insert` guard blocks self-publishing.
- Unsubscribe GET and email-change confirm change state, but are authorised by HMAC / `wp_hash` tokens compared with `hash_equals`.
- `/auth/app-password`: rate-limited per IP and per username before `wp_authenticate`.
- Admin handlers: all 14 admin-post/AJAX handlers check capability and nonce.
- Search SQL: ORDER BY from a switch, IN() placeholders, LIKE via esc_like.
- Importer sideload uses `download_url` (wp_safe_remote_get), admin only.
