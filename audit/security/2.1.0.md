## Scanner-visible but safe

- Review reply: `wb_listora_user_can_reply_to_review()` - logged in, replies enabled, then admin, review moderator or the listing author; `listing_id` read from the review row, not the request. The Reply button uses the same helper.
- Owner listing delete / deactivate / reactivate / renew: `require_listing_owner()` (author or `edit_others_listora_listings`).
- `wb_listora_user_can_moderate_listings()`: administrators, editors and Listora Moderators only; narrows access (WooCommerce Shop Manager loses it), widens it to nobody.
- Search SQL (`includes/search/`): every new predicate uses placeholders (custom-field EXISTS, field `IN()`, taxonomy, location LIKE via `esc_like`, event dates, Open-now id list, radius); `distance_sql()` unit is one of two constants, alias stripped to `[a-z0-9_]`; sort is a fixed switch. Runtime probe with quote and `OR 1=1` payloads in keyword, location, tags and `price_range[]`: 200, no DB error.
- Stored XSS: new `data-wp-context` uses go through `wp_interactivity_data_wp_context()` or `esc_attr( wp_json_encode() )`; "Listed by" link and credit notes escaped; no new dynamic `innerHTML` in `src/`.
- CSV export: REST streams to `php://output` (the old file in public uploads is gone); WP-CLI writes to `wp_tempnam()`; both need `manage_options`; cells escaped against formula injection.
- Setup wizard: capability + nonce; the `done` step needs a per-user finish transient; map provider allowlisted.
- Claims: a failed insert deletes the proof files and changes no ownership.
- Guest login modal: printed only for logged-out visitors; return URL through `esc_url` / `wp_login_url`.
- Category colour helper `wb_listora_category_color()`: reads term meta / type colour only; output escaped by every caller (tile `esc_attr`, REST JSON, calendar JSON).
