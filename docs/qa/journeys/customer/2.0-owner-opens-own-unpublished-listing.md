# A member can open their own rejected, paused and unpaid listings; everyone else gets a 404; expired shows a notice

Core WordPress hides a non-public post from anyone without `edit_post`, so a Subscriber owner used to get a 404 on the "View" link of their own rejected listing. 2.0.0 hands the listing back to its author (read-only preview with the owner bar), keeps the 404 for everyone else, and visitors to an EXPIRED listing (a public status) see a short notice.

## Steps

### 1. Where the owner starts: the dashboard lists them (member-owner, 1440)
- **Action**: `$SITE_URL/my-listings/?autologin=qa_vendor_01`.
- **Expect**: the My Listings tab lists "J20 Owner Published", "J20 Owner Pending", "J20 Owner Rejected", "J20 Owner Paused", "J20 Owner Awaiting Payment", "J20 Owner Expired", each with a View link. For the non-public ones the link is the plain-ID form `/?post_type=listora_listing&p=<id>` (they have no public permalink); for Published/Expired it is `/listing/<slug>/`.

### 2. Owner opens each non-public listing (the fix)
Use the View links from step 1 (also reachable by typing the URL):
| Fixture | Status | Owner bar chip (`.listora-detail__owner-bar-status`) |
|---|---|---|
| J20 Owner Pending | pending | `is-pending` "Pending review" |
| J20 Owner Rejected | listora_rejected | `is-rejected` "Rejected" |
| J20 Owner Paused | listora_deactivated | `is-deactivated` "Deactivated" |
| J20 Owner Awaiting Payment | listora_payment | `is-paused` "Awaiting credits" |
- **Expect** for each: HTTP 200; `<title>` = the listing title; an `aside.listora-detail__owner-bar[aria-label="Manage this listing"]` containing "You're viewing this as the owner.", the status chip above, an "Edit listing" link to `/my-listings/?tab=listings&action=edit&id=<id>` and a "My dashboard" link; the page is a read-only preview: the owner gets no contact form and no review form (an admin viewing the same URL does, so this is the owner rule, not a missing template).
- **On fail**: `Status_Manager::remember_owned_unpublished` / `restore_owned_unpublished` (`includes/workflow/class-status-manager.php` ~174-205), `blocks/listing-detail/render.php` (~330).

### 3. Everyone else still gets the 404 (positive control for step 2)
Same four URLs, same run, as each rung:
| Rung | Expect |
|---|---|
| member-other (dana_whitfield) | 404, `<title>` "Page not found" |
| unrelated Subscriber (tester) | 404 |
| anonymous | 404 |
| administrator (control) | 200 with the owner bar (admins can always preview) |
- **Expect**: the owner got 200 in step 2 with the SAME URLs, so the 404s here are the access rule, not a broken route.

### 4. Expired listings: visitors see a notice, owner does not (1440)
- **Action**: open `/listing/j20-owner-expired/` as anonymous and as dana_whitfield.
- **Expect**: HTTP 200 (expired is a public status; the page is not removed); one `p.listora-detail__expired-notice[role="note"]` reading "This listing has expired, so its details may be out of date."; response header `X-Robots-Tag: noindex`; no owner bar.
- **Action**: same URL as qa_vendor_01 and as admin.
- **Expect**: owner bar with chip `is-expired` "Expired" and NO expired notice (the owner has the bar instead).
- **Action**: a mu-plugin `add_filter( 'wb_listora_expired_listing_notice', '__return_empty_string' );`
- **Expect**: visitors see no notice at all (the documented off switch). Remove the mu-plugin.
- **On fail**: `blocks/listing-detail/render.php` (~408), `Plugin::handle_expired_listing` (`includes/class-plugin.php` ~1105).

### 5. Read-only means read-only
- **Action**: as the owner on the rejected listing, `wp.apiFetch({path:'/wp/v2/listings/<id>',method:'POST',data:{title:'hacked'}})`.
- **Expect**: 403 `rest_cannot_edit` (a Subscriber owner cannot edit through the core route; edits go through the dashboard form which uses `wb_listora_user_can_edit_listing`). The title is unchanged.

### 6. Search and archives never leak them
- **Action**: as anonymous and dana, search the Directory for "J20 Owner" and open `/listing-category/<slug>/` pages.
- **Expect**: only "J20 Owner Published" appears (an expired listing keeps its own page but is not in search); Rejected, Paused, Awaiting Payment and Pending never do. `GET /listora/v1/listings/<rejected id>`: dana 403 `rest_forbidden`, anonymous 401 `rest_forbidden`, owner 200.

### 7. 390px
- **Expect**: owner bar wraps (status chip above, buttons below), no horizontal scroll, "Edit listing" and "My dashboard" >= 40px tall; the expired notice wraps and keeps contrast in dark mode.

## Pass criteria

1. The Subscriber owner opens their pending, rejected, paused and awaiting-payment listings (200 + owner bar + correct chip).
2. Another member, an unrelated Subscriber and a visitor get 404 for the same URLs, in the same run.
3. Expired listings show visitors the notice, noindex header, and show the owner their bar instead.
4. The preview cannot be used to edit or to find the listing through search.

## Fail diagnostics

| Symptom | Likely cause | File |
|---|---|---|
| Owner still gets 404 | `posts_results`/`the_posts` pair not registered, or custom status not `protected` | `class-status-manager.php`, `class-post-types.php` status registration |
| Everyone gets 200 | restore ignores the author check | `remember_owned_unpublished` author comparison |
| No expired note | filter returned empty or status mismatch | `listing-detail/render.php` |
| Owner sees the visitor note too | `$listora_owner_view` false for owner | `listing-detail/render.php` ~330 |
