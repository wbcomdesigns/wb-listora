# A visitor's contact message becomes a lead the owner can read

2.0.0 saves every contact-form message as a lead BEFORE it emails anyone, so a failed mail never loses an enquiry. The owner reads it in My Dashboard > Leads and in their inbox, the site owner reads every lead in wp-admin (see `admin/2.0-leads-admin-retention-privacy-ownership.md`). This journey is the visitor-to-owner path; the short sentinel `regression/lead-counted-without-analytics.md` covers only the analytics counter.

## Setup

- `$LISTING_URL` = permalink of "J20 Owner Published" (`wp post list --post_type=listora_listing --s="J20 Owner Published" --field=url`).
- Baselines (WP-CLI):
  ```bash
  wp eval 'global $wpdb; echo $wpdb->get_var("SELECT COUNT(*) FROM {$wpdb->prefix}listora_leads");'   # LEADS_BASE
  wp eval 'global $wpdb; echo $wpdb->get_var("SELECT COALESCE(MAX(id),0) FROM {$wpdb->prefix}listora_email_log");'   # MAIL_BASE
  ```
- The form allows 3 messages per hour per sender per listing, so send exactly one message per rung below and wait out the hour (or use a different listing) before re-running.

## Steps

### 1. Visitor sees the form (anonymous, 1440)
- **Action**: logged out, open `$LISTING_URL`.
- **Expect**: a `.listora-contact-form` block with heading "Contact owner" and inputs labelled "Your name *", "Your email *", "Phone (optional)", "Message *", and a button "Send message". The honeypot `input[name=hp]` is off-screen and `aria-hidden`.
- **On fail**: `includes/class-contact-form.php::render_form`, `templates/blocks/listing-detail/sidebar.php`.

### 2. Guest sends a message with a phone number
- **Action**: Your name `J20 Guest`, Your email `j20-guest@example.com`, Phone `+1 555 0100`, Message `J20 lead message, please call me back.` then "Send message".
- **Expect**: the `.listora-contact-form__message--success` live region (aria-live=polite) shows "Your message has been sent to the listing owner.", the fields are cleared (`form.reset()`) and the page does not reload. Network: `POST /wp-json/listora/v1/listings/<id>/contact-form` returns 200 `{"sent":true,...}`.
- **On fail**: `Contact_Form::handle_submit`; 403 `rest_forbidden`-style nonce failure means the honeypot/nonce field was stripped by a cache plugin.

### 3. DB: the lead exists and belongs to the owner
- **Action**:
  ```bash
  wp eval 'global $wpdb; print_r($wpdb->get_row("SELECT listing_id,owner_id,sender_id,name,email,phone,message FROM {$wpdb->prefix}listora_leads ORDER BY id DESC LIMIT 1", ARRAY_A));'
  ```
- **Expect**: count = LEADS_BASE + 1; `owner_id` = qa_vendor_01's ID (6 here); `sender_id` = 0 (guest); `name`/`email`/`phone`/`message` exactly as typed.
- **On fail**: `Leads::record` (`includes/core/class-leads.php`).

### 4. The owner is emailed, branded, and Reply goes to the sender
- **Action**: read the email in the mail catcher, or:
  ```bash
  wp eval 'global $wpdb; print_r($wpdb->get_row("SELECT event_key,recipient,subject,success,headers FROM {$wpdb->prefix}listora_email_log WHERE id > MAIL_BASE ORDER BY id DESC LIMIT 1", ARRAY_A));'
  ```
- **Expect**: `event_key` = `lead_received`; `recipient` = `qa_vendor_01@directory.local`; `subject` = `New message from J20 Guest about J20 Owner Published`; `success` = 1; headers contain `Reply-To: J20 Guest <j20-guest@example.com>`. The body carries the sender's phone and message, the header title "New message from a visitor", and the footer "This email was sent by <site name>.".
- **On fail**: `Notifications::lead_received` (~line 940), `Notifications` Reply-To block (~line 1560), `templates/emails/parts/header.php` / `footer.php`.

### 5. Owner reads it in My Dashboard > Leads (member-owner, 1440 then 390)
- **Action**: `$SITE_URL/my-listings/?autologin=qa_vendor_01&tab=leads`.
- **Expect**: sidebar tab "Leads" is present; tab title "Leads"; a `.listora-dashboard__lead-row` with `.listora-dashboard__lead-title` = "J20 Guest", the listing link "J20 Owner Published", the message text, a "Reply by email" button whose href starts `mailto:j20-guest@example.com?subject=Re%3A%20J20%20Owner%20Published`, and a `tel:+15550100` button labelled "+1 555 0100".
- **Expect (390)**: the row stacks, no horizontal page scroll, both action buttons >= 40px tall.
- **On fail**: `Leads_Dashboard_Tab::render_panel`, `templates/blocks/user-dashboard/tab-leads.php`.

### 6. Role ladder
| Rung | Action | Expect |
|---|---|---|
| member-owner (qa_vendor_01) | step 5 | sees the lead |
| member-other (dana_whitfield, no listings, no leads) | `/my-listings/?autologin=dana_whitfield&tab=leads` | NO "Leads" tab in the sidebar; the page falls back to the Overview (document title "My Listings") |

| member-owner | `wp.apiFetch({path:'/listora/v1/leads'})` | 200, array contains the lead, headers `X-WP-Total` >= 1 |
| administrator (control) | `/wp-admin/admin.php?page=listora-leads` | lists the lead (see the admin journey) |

### 7. Positive control: the owner does not get a form on their own listing
- **Action**: as qa_vendor_01 open `$LISTING_URL`.
- **Expect**: NO `.listora-contact-form` (an owner cannot message themselves). As dana_whitfield the form IS present (this proves step 1's form is not simply missing for logged-in users).
- **On fail**: `Contact_Form::render_form` own-listing guard.

### 8. Refused messages are not saved
- **Action**: as the guest, submit with an invalid email through the API: `wp.apiFetch({path:'/listora/v1/listings/<id>/contact-form',method:'POST',data:{name:'x',email:'nope',message:'hi'}})`.
- **Expect**: 400 `listora_invalid_email` ("Please provide a valid email address."); lead count unchanged.

## Pass criteria

1. Guest message returns 200 and shows the confirmation text.
2. One `listora_leads` row exists with owner = listing author, sender 0, phone saved.
3. One `lead_received` email, success = 1, Reply-To is the sender.
4. Owner sees it under My Dashboard > Leads with working mailto/tel actions; no other member sees it, and a member with nothing to show has no Leads tab.
5. The listing owner is never shown their own contact form.

## Fail diagnostics

| Symptom | Likely cause | File |
|---|---|---|
| 200 but no lead row | `Leads::record` failed, table missing | `class-leads.php::create_table`, activator/migrator |
| Lead saved, no email | feature mail toggle off (Settings > Notifications "New message from a visitor") or `wb_listora_should_send_notification` | `Notifications::should_send` |
| Email has no Reply-To | header block skipped for non-`lead_received` path | `class-notifications.php` ~1560 |
| Dana sees a Leads tab | `Leads_Dashboard_Tab::visible_to` ignoring ownership | `class-leads-dashboard-tab.php` |
| Lead visible to another member via REST | `Leads::user_can_manage` regression | `class-leads.php`, `class-leads-controller.php::item_permission` |
