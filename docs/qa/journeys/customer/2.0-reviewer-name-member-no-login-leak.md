# A member who never chose a display name is "Member", with no login in links, embeds or feeds

A WordPress login is half of someone's credentials and BuddyPress/author-archive URLs are built from it. 2.0.0 resolves every public member name through one rule (`wb_listora_user_public_name()`): the display name, or empty while it is still the login. Reviews then read "Member", profile links are dropped, and listing embeds, feeds and bylines name the listing's public owner instead of the account.

## Steps

### 1. Reviewer reads "Member" on the listing page (anonymous, 1440)
- **Action**: open `$SITE_URL/listing/j20-owner-published/`, Reviews tab (`#tab-reviews`).
- **Expect**: the review by `tester` shows `strong.listora-detail__review-author` = "Member"; its avatar `img.listora-detail__review-avatar` has `alt="Member"`; the author is NOT a link; the time reads "x seconds ago"/"x minutes ago" for a review made just now (never "4 hours ago"); the stars are announced "Rated 4 out of 5".
- **Positive control**: view-source / DOM search for the string `tester` in the visible page: 0 matches (login absent). A review written by a NAMED member (add one as qa_vendor_02 or use demo reviews) shows their real display name, proving the rule is not "everyone is Member".
- **On fail**: `wb_listora_review_author_name()` (`includes/class-template-helpers.php` ~2205), `templates/blocks/listing-detail/tabs.php` review loop.

### 2. Same on the Reviews block and the REST payload
- **Action**: on a page with the Reviews block (`.listora-reviews__reviewer`) for the same listing; and `GET /wp-json/listora/v1/listings/<id>/reviews` as anonymous.
- **Expect**: block shows "Member" as a `span.listora-reviews__reviewer` (no `--link` class, no `href`); JSON `user_name` = "Member", `user_profile_url` = "" for that review. The JSON still exposes a numeric `user_id`; note it in the run log but it is not a login.
- **Read-back** (logged out): `curl -s $SITE_URL/wp-json/listora/v1/listings/<id>/reviews | grep -c '<reviewer login>'` is 0 and `jq '.reviews[]|select(.user_name=="Member")|.user_profile_url'` prints only `""`; the same for `.../oembed/1.0/embed?url=<listing url>` `author_name` and `author_url`. **fails_on**: 2394e3c (login visible in profile links and oEmbed). Pro's journey `customer/09` asserts the link only for a NAMED member. Not verified live.
- **On fail**: `templates/blocks/listing-reviews/review-card.php` (~32), `Reviews_Controller` item shaper (`user_profile_url`, ~409).

### 3. Former and deleted members keep their stand-ins
- **Action**: `wp eval 'global $wpdb; $wpdb->update($wpdb->prefix."listora_reviews",["user_id"=>999999],["id"=><review_published id>]);'` then reload; restore `user_id` afterwards.
- **Expect**: the author reads "Former member"; a review row with `user_id` 0 reads "Anonymous". Restore the row before continuing.

### 4. The listing owner's name (anonymous)
- **Action**: open `$SITE_URL/listing/j20-unnamed-member-listing/` (owner `tester`, no public contact name).
- **Expect**: no "Listed by"/owner-name row (`.listora-detail__owner-name` absent), no link to `/author/tester/`, no `tester` in the visible page, no `author` object in the JSON-LD. Control: `/listing/j20-owner-published/` DOES show "QA Vendor 01" (named owner).
- **Opt-in**: `add_filter( 'wb_listora_owner_name_use_real_name', '__return_true' );` shows first + last name when the account has them (never the login). Remove after.
- **On fail**: `wb_listora_get_listing_owner_name()` / `wb_listora_user_public_name()` (`includes/helpers.php` ~388-460).

### 5. oEmbed names the public owner, never the account
- **Action**:
  ```bash
  curl -s "$SITE_URL/wp-json/oembed/1.0/embed?url=$SITE_URL/listing/j20-unnamed-member-listing/" | jq '{author_name,author_url,title}'
  curl -s "$SITE_URL/wp-json/oembed/1.0/embed?url=$SITE_URL/listing/j20-owner-published/" | jq '{author_name,author_url}'
  ```
- **Expect**: unnamed: `author_name` and `author_url` are absent/null. Named: `author_name` = "QA Vendor 01", `author_url` = the LISTING URL (not `/author/...`).
- **On fail**: `Plugin::listing_oembed_author` (`includes/class-plugin.php` ~463).

### 6. Feeds and bylines
- **Action**: `curl -s "$SITE_URL/listing/feed/"` (the listing post-type feed).
- **Expect**: `<dc:creator>` for "J20 Unnamed Member Listing" is empty, for "J20 Owner Published" is "QA Vendor 01"; the string `tester` appears nowhere in the XML. `the_author()` in theme bylines on a listing page follows the same rule (`Plugin::listing_public_author`).

### 7. Profile links are suppressed for the unnamed
- **Action**: with BuddyPress active (it is on this site), open a listing whose owner or reviewer is `tester`.
- **Expect**: no `href` to `/members/tester/` anywhere (reviewer, owner, "reply" author). For qa_vendor_01 the link may exist (named).
- **Filter check**: `wp eval 'echo apply_filters("wb_listora_member_profile_url","http://x/members/tester/", get_user_by("login","tester")->ID);'` prints an empty string.
- **On fail**: `Plugin::hide_unnamed_member_profile_url` (priority 20 so it runs after BuddyPress's own answer).

## Pass criteria

1. An unnamed reviewer reads "Member" with no link; a named one reads their display name.
2. No public surface (page, block, REST, oEmbed, feed, JSON-LD, byline) contains the unnamed member's login.
3. Former/deleted/guest authors read "Former member" / "Anonymous".
4. Named members are unaffected (control).
