# The Directory can show only featured listings, and the Featured block's "See all" lists them all

2.0.0 added `listora_featured=1` to the Directory, and the Featured block's "See all" now points there (it used to open the theme's blog archive). The filter has no toggle control of its own: it is reached from "See all" or a link, and it behaves like any other filter (counted in the Filters badge, cleared by Clear all, composes with type and sort).

## Setup

- Reference numbers:
  ```bash
  wp eval 'global $wpdb; echo $wpdb->get_var("SELECT COUNT(*) FROM {$wpdb->prefix}listora_search_index WHERE is_featured=1");'   # FEAT
  wp eval 'echo rest_do_request(new WP_REST_Request("GET","/listora/v1/search"))->get_data()["total"];'   # ALL
  ```
  FEAT is the featured count of PUBLISHED listings in the search index; ALL is every published listing.

## Steps

### 1. "See all" goes to the Directory, not the archive (anonymous, 1440)
- **Action**: open the Home page. In the Featured block click the "See all →" link (`a.listora-featured__see-all`).
- **Expect**: the link's href is `<Directory>/?listora_sort=featured&listora_featured=1` (plus `listora_type=<slug>` when the block is pinned to a type); you land on the Directory page, not `/listing/` and not a blog list.
- **On fail**: `blocks/listing-featured/render.php` (~line 86), `templates/blocks/listing-featured/featured.php`.

### 2. The Directory shows only featured listings
- **Expect**: `.listora-grid__count` reads "Showing 1–N of FEAT listings" (FEAT from Setup, allow +/-1 for a listing featured in between); the Filters badge counts 1; every card carries the featured badge (`.listora-card__badge-featured`); sort control reads "Featured".
- **Positive control**: `/listings/` without the parameter shows ALL listings and non-featured cards without the badge, so FEAT < ALL proves the filter bites.
- **Expect**: paging (`listora_page=2`) keeps `listora_featured=1` in every page link; `listora_page=999` shows the last page.

### 3. It composes with other filters
- **Action**: `/listings/?listora_featured=1&listora_type=hotel`, then add `&listora_keyword=<word in a featured hotel title>`.
- **Expect**: the total is the featured hotels only (<= FEAT), then narrows further; removing `listora_featured` from the URL grows the total.
- **Action**: use "Clear all" in the search block.
- **Expect**: `listora_featured` leaves the URL and the full directory returns (the badge returns to 0).

### 4. Featured status is honest
- **Action**: as administrator, un-feature one listing (Listings > edit > Featured box, or `wp post meta update <id> _listora_is_featured 0` then `wp listora reindex`).
- **Expect**: the count drops by one on reload; the listing keeps appearing in the unfiltered directory. Re-feature it afterwards.
- **Action**: a listing whose featured period ended (`_listora_featured_until` in the past) must not count (run `wp listora cleanup` first).
- **On fail**: `Featured` service / cron `featured expiry`, `Search_Engine` `featured_only` (class-search-engine.php ~451).

### 5. Empty and edge states
- **Action**: `/listings/?listora_featured=1&listora_keyword=zzzz-no-match`.
- **Expect**: the Directory empty state ("No listings found" with a way to clear filters), HTTP 200, no PHP notice.
- **Action**: `/listings/?listora_featured=0` and `?listora_featured=yes`.
- **Expect**: both treated as "off" (only `1` activates the filter): full directory.

### 6. The block itself, with nothing featured
- **Action**: temporarily make no listing featured (or use a Featured block pinned to a type with none).
- **Expect**: the block renders the shared empty state "No featured listings yet - Listings marked as featured will appear here." and NO "See all" link.

### 8. 390px
- **Expect**: "See all" stays visible next to the block title or wraps below it; tap target >= 40px; carousel arrows do not overlap it; no horizontal page scroll.

## Pass criteria

1. "See all" targets the Directory with `listora_featured=1`.
2. The filtered total equals the published featured count and every card shows the featured badge.
3. The filter composes, pages and clears like any other filter.
4. Un-featuring and expiry change the count; an empty block has no dead "See all".
