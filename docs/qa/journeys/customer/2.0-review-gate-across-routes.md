# One gate for every action on an existing review

2.0.0 routes edit, helpful vote, report, owner reply (and Pro's photo upload) through `wb_listora_review_gate()`: the review must exist, reviews must be on for its listing (site switch AND the listing type), and for votes, reports and replies the review must be published, because nobody but its author and moderators can see a pending one. Editing checks the same minimum length as writing, in characters. Own-review DELETE is deliberately NOT gated.

## Setup

`R_PUB` = approved review ID (by tester), `R_PEND` = pending review ID (by dana_whitfield), `L` = the listing ID. Both printed by the seed script (`review_published`, `review_pending`).

## Steps

### 1. Edit checks the same minimum as create (member-owner of the review: dana)
| Call | Expect |
|---|---|
| `PUT /reviews/R_PEND {"content":"short"}` | 400 `listora_review_too_short` "Review must be at least 20 characters." |
| `PUT /reviews/R_PEND {"content":"<19 x é>"}` | 400 (counted in characters, 19 < 20, even though it is 38 bytes) |
| `PUT /reviews/R_PEND {"content":"<20 x é>"}` | 200 `{"updated":true}` (20 characters pass) |
| `PUT /reviews/R_PEND {"content":"J20 edited review text that is long enough to pass"}` | 200 |
- **Positive control**: the last call succeeds, so the 400s are the length rule and not a broken route.
- **fails_on**: 2394e3c (PUT /reviews skipped the minimum-length rule; card 10393672617). Not verified live.
- **On fail**: `Reviews_Controller::validate_review_content` (`includes/rest/class-reviews-controller.php` ~1031) must be called from the update path as well as create.

### 2. Votes, reports and replies are refused on a pending review
As member-other (qa_vendor_01 is the listing owner; tester is another member):
| Call | Expect |
|---|---|
| `POST /reviews/R_PEND/helpful` (tester) | 403 `listora_review_not_approved` "This review is not published yet." |
| `POST /reviews/R_PEND/report {"reason":"spam"}` (tester) | 403 `listora_review_not_approved` |
| `POST /reviews/R_PEND/reply {"content":"thanks"}` (qa_vendor_01, the owner) | 403 `listora_review_not_approved` |
| `POST /reviews/R_PUB/helpful` (qa_vendor_01 or dana) | 200 `{"helpful_count":1}` (positive control: the published review accepts it) |
| `POST /reviews/999999/helpful` | 404 `listora_not_found` "Review not found." |
- **Expect**: after the 403s `SELECT COUNT(*) FROM wp_listora_review_votes WHERE review_id = R_PEND` is 0, and no report option row exists for R_PEND.
- **fails_on**: 2394e3c (pending reviews took helpful votes and reports; card 10393672671). Also run it as a THIRD member (not the author, not the owner) for helpful and report, so the refusal is the pending state and not ownership. Not verified live.

### 3. Pending review is invisible to everyone but its author and moderators
- **Action**: as anonymous and as tester open `/listing/j20-owner-published/` Reviews tab.
- **Expect**: only the published review (as "Member") is listed; the pending text is absent. As dana (author) and as admin (Moderation > Reviews) it is visible with a Pending badge.

### 4. Reviews off for the listing's TYPE closes every route
- **Action**: set the listing's type Reviews = "Off for this type" (Listing Types editor; or on a scratch type per `admin/2.0-per-type-moderation-and-reviews-take-effect.md`).
- **Expect** (any member, same IDs):
| Call | Expect |
|---|---|
| `GET /listings/L/reviews` | 403 `listora_reviews_disabled` |
| `POST /listings/L/reviews {...}` | 403 `listora_reviews_disabled` |
| `PUT /reviews/R_PEND {...valid text}` | 403 `listora_reviews_disabled` |
| `POST /reviews/R_PUB/helpful` | 403 `listora_reviews_disabled` |
| `POST /reviews/R_PUB/report` | 403 `listora_reviews_disabled` |
| `POST /reviews/R_PUB/reply` (owner) | 403 `listora_reviews_disabled` |
| `DELETE /reviews/R_PEND` (dana, own review) | 200 (members can still remove what they wrote) |
- **Restore** the type to "Use the site setting" and re-run `PUT /reviews/R_PEND` to prove 200 again.
- **fails_on**: d7aa3821 (edit, reply, helpful and report each had their own, weaker check; card 10393575233). The strict-type half of that card is `customer/02-submit-a-listing-wizard-end-to-end.md` step 22 ("A term ID is not a listing type"). Not verified live.
- **On fail**: `wb_listora_review_gate` (`includes/helpers.php` ~905) and the permission callbacks in `class-reviews-controller.php` (~1068-1215); Pro's review-photo route must call the same gate (see Pro journeys).

### 5. Site switch
- **Action**: Settings > Features > "Reviews & Ratings" off.
- **Expect**: same 403 `listora_reviews_disabled` table for every listing, every type. Turn it back on.

### 6. Authorisation still applies after the gate
| Rung | Call | Expect |
|---|---|---|
| anonymous | `PUT /reviews/R_PEND` | 401 `listora_unauthorized` |
| member-other (tester) | `PUT /reviews/R_PEND` (not theirs) | 403 `listora_forbidden` |
| member-other | `PUT /reviews/R_PEND {"status":"approved"}` as the author | 403 `listora_forbidden_status` (authors cannot self-approve) |
| qa_editor (moderator) | `PUT /reviews/R_PEND {"status":"approved"}` | 200 |
| administrator | any of the above | 200 (control) |

### 7. Vote rules still hold behind the gate
- **Action**: tester (author of R_PUB) `POST /reviews/R_PUB/helpful`; then dana twice.
- **Expect**: author voting on own review 403 `listora_own_review`; dana first vote 200 `{"helpful_count":1}`, second 409 `listora_already_voted`; none of them 429 (`review_vote` is 300 per hour per account, so one member's votes never throttle another's on the same IP).

## Pass criteria

1. Edit enforces the same character minimum as create.
2. Helpful, report and reply on a pending review: 403 `listora_review_not_approved`, nothing stored; missing review: 404.
3. Reviews off (type or site) returns 403 `listora_reviews_disabled` on read, create, edit, vote, report, reply, but DELETE of an own review still works.
4. Capability rules (401/403/`listora_forbidden_status`) still apply on top of the gate.
