# An old or hand-edited page number shows the last page, not "Showing 1,961-127 of 127"

An old bookmark (`?listora_page=99`) after listings were removed used to render an empty grid with a nonsense count. 2.0.0 shows the last real page on the Directory and on the dashboard Leads tab. This journey walks every paged list surface on a big site so a clamp that exists in one place and not another is caught.

> Known gap found while writing this journey (verify, do not assume): at e4f9f093 the Listora wp-admin tables built on `Admin_Table` (Reviews, Email Log, Claims, Leads) answer a past-the-end `paged` with the EMPTY STATE ("No reviews yet") although rows exist. Step 3 asserts the correct behaviour, so it is expected to FAIL there.

## Setup

```bash
wp eval 'global $wpdb; echo $wpdb->get_var("SELECT COUNT(*) FROM {$wpdb->posts} WHERE post_type=\"listora_listing\" AND post_status<>\"auto-draft\"");'   # ROWS (2809)
wp eval 'echo rest_do_request(new WP_REST_Request("GET","/listora/v1/search"))->get_data()["total"];'                                              # PUB (published)
```
Last Directory page = ceil(PUB / 20).

## Steps

### 1. Directory (anonymous, 1440)
- **Action**: open `$SITE_URL/listings/?listora_page=1`, then `?listora_page=<last>`, `?listora_page=<last+1>`, `?listora_page=999999`.
- **Expect**: page 1 reads "Showing 1–20 of PUB listings"; `<last>` reads "Showing <20*(last-1)+1>–PUB of PUB listings"; both beyond-the-end URLs render the SAME as `<last>` (same count text, cards, and `a.listora-grid__page-num.is-active[aria-current="page"]` = last). Never "Showing N–M" with N > M, never a blank grid.
- **Positive control**: page 2 reads "Showing 21–40" in the same run.
- **Expect**: `listora_page=0`, `-3`, `abc` behave as page 1.
- **Expect (pager)**: "Previous page" button enabled and "Next page" disabled on the last page; at most 7 numbered links with ellipses; every link keeps active filters (`?listora_type=...&listora_page=n`).
- **On fail**: `blocks/listing-grid/render.php` (~72), `templates/blocks/listing-grid/pagination.php`.

### 2. Directory with a filter that leaves 1 page
- **Action**: `?listora_keyword=<a rare word>&listora_page=50`.
- **Expect**: page 1 of the filtered set; no pager when only one page ("Showing 1–k of k").

### 3. wp-admin tables (administrator)
- **Action**: `$SITE_URL/wp-admin/admin.php?page=listora-reviews&status=all&paged=999` (and `listora-email-log`, `listora-claims`, `listora-leads` the same way).
- **Expect (contract)**: the last page of rows with the count text still right ("<n> reviews"), numbered pager on the last page; NOT the empty state. Record the actual outcome: at e4f9f093 it shows "No reviews yet / Reviews appear here as visitors rate your listings." (FAIL: the empty state lies about the data; the view tabs above it still say "All 121").
- **Positive control**: `...&status=all` (no paged) lists 20 rows and "<n> reviews", so the table is not simply empty.
- **On fail**: `includes/admin/class-admin-table.php` (`request()` ~58 reads `paged` with no upper bound; `render()` ~544 builds the pager from `total`).

### 4. Native Listings list (administrator, 2809 rows)
- **Action**: `$SITE_URL/wp-admin/edit.php?post_type=listora_listing&paged=999`.
- **Expect**: WordPress redirects (302) to the last page (`paged=141` at 20 per page); the table shows "2,809 items" and 9 rows; sort by title and filter by status keep working; bulk actions are available.
- **Filter + sort at scale**: filter Status = Published (count tabs: All 2,809 | Published ~100 | Draft ~2,700), sort by Title; response < 3 s and no PHP notice in `debug.log`.

### 5. Member dashboard tabs (member-owner/administrator, 1440)
- **Action**: as administrator (owns 100+ listings) `$SITE_URL/my-listings/?tab=listings&listings_page=999`.
- **Expect**: the last page (a partial page of rows, "Page N of N"), never an empty "No listings yet". `?tab=leads&leads_page=999` (as author1, 3 leads) shows all 3 rows, verified. For `?tab=reviews&reviews_page=999` and `?tab=favorites&favorites_page=999` record the outcome per tab (the whole dashboard is server-rendered with every pane in the DOM, so read the ACTIVE pane `#dash-panel-<tab>`, not the first pager on the page); the full per-tab pager contract is `regression/dashboard-tab-pagination.md`.
- **Expect (tab filter)**: the status filter and the count badge agree with the list (see `regression/dashboard-badge-counts-every-status.md`).

### 6. Counts come from COUNT(*), not from loading rows
- **Action**: with Query Monitor (or `SAVEQUERIES`) on page 1 of the Directory and of the admin Listings list.
- **Expect**: one count query per list and `LIMIT 20` on the row query; no per-row listing meta query inside the loop (cards use primed caches). Page generation stays flat when going from 100 to 2,800 rows.

### 7. 390px
- **Expect**: the pager wraps (prev/next 40px, numbers 40px), no horizontal scroll, the count text sits above the grid; wp-admin tables stack rows under 480px.

## Pass criteria

1. Every paged list surface shows the last real page for an out-of-range page number.
2. Counts and pagers agree with the data on a 2,800-row site; no unbounded query.
3. Invalid page numbers fall back to page 1.
