# Category, location, tag, feature and type pages are the Directory, filtered

Before 2.0.0 a term URL used the theme's blog archive (no search, no map, "Read More" cards). Now the request is routed to the Directory page with the term as the filter, titled and bread-crumbed by the term, and the bare `/listing/` archive redirects to the Directory. Short sentinel: `regression/term-archives-render-directory.md`; this one adds the role ladder, paging, escape hatch and the theme matrix.

## Steps

### 1. Each term URL renders the Directory (anonymous, 1440)
For each of `/listing-category/casual/`, `/listing-location/us/ny/`, `/listing-tag/waterfront/`, `/listing-feature/wifi/`, `/listing-type/hotel/`:
- **Expect**: HTTP 200; `<h1>` = the term name (Casual, New York, waterfront, WiFi, Hotel); `<title>` = "<term name> - <site name>" (here "Casual – Listora"); `body` has `listora-term-archive` and `listora-term-archive--<taxonomy>` (e.g. `listora-term-archive--listora_listing_cat`); `<link rel="canonical">` = the term URL itself.
- **Expect**: a breadcrumb `nav.listora-term-archive__crumbs[aria-label="Breadcrumb"]` reading "Directory › <term name>" whose first link is the Directory URL and whose last item has `aria-current="page"`.
- **Expect**: the Directory UI is present (`.listora-search`, `.listora-grid__count`, cards `.listora-card`); the count `Showing 1–N of T listings` has T = the term's `count`:
  ```bash
  wp term get listora_listing_cat casual --by=slug --field=count   # 6
  ```
- **Expect**: no theme blog chrome: no "Read More" link, no post-date/author byline on cards.
- **On fail**: `includes/core/class-term-archives.php::route_term_archive` (request filter), `Page_Registry::get_id('directory')`.

### 2. Description and the intro filter
- **Action**: Categories > Casual > Description = `J20 intro text`, Update.
- **Expect**: the page shows it in `.listora-term-archive__desc` under the breadcrumb. Remove it again: the div disappears (it is not an empty box).
- **Action**: a mu-plugin `add_filter( 'wb_listora_term_archive_intro', fn( $html, $term ) => '<p class="j20-intro">J20 hello</p>', 10, 2 );`
- **Expect**: `.j20-intro` replaces the default intro. Remove the mu-plugin.

### 3. Paging and filters keep the term
- **Action**: open `/listing-feature/wifi/` (38 listings, 2 pages at 20 per page).
- **Expect**: page 2 link is `/listing-feature/wifi/?listora_page=2` (the term URL, not `/listings/?...`); it shows "Showing 21–38 of 38 listings"; `?listora_page=999` shows the last page, never "Showing 1,961-127 of 127".
- **Action**: type a keyword in the search and run it with Enter.
- **Expect**: results narrow to a subset of the term's listings (every card is still in the term; spot-check one with `wp post term list <id> listora_listing_feature --field=slug`). Record what "Clear all" does here (term list vs whole directory) in the run notes; the contract is that it never shows listings outside the term while the term URL is open.

### 4. Bare archive and unknown terms (positive control for step 1)
- **Action**: `curl -sI $SITE_URL/listing/`.
- **Expect**: `301` with `Location: $SITE_URL/listings/` (the Directory page).
- **Action**: `curl -sI $SITE_URL/listing-category/no-such-term/`.
- **Expect**: `404`. A real term that has zero published listings returns 200 with the Directory's empty state ("No listings found"), not a 404.
- **Positive control**: `/listing-category/casual/` is 200 in the same run, so the 404 above is the unknown term and not a broken route.

### 5. Single listings are untouched
- **Action**: open any `/listing/<slug>/`.
- **Expect**: the normal listing page (the redirect only hits the archive, not singles); its category chip links to the term page from step 1.

### 6. Role ladder
| Rung | Expect |
|---|---|
| anonymous | steps 1-5 |
| member-other (dana_whitfield) | identical output; no owner bar, no admin links |
| administrator (control) | identical output plus the admin bar; the term page does NOT show draft/pending listings (count unchanged) |
| listing owner of a pending listing in the term | the pending listing is not counted or listed on the term page (visible only in My Dashboard) |

### 7. Escape hatch
- **Action**: mu-plugin `add_filter( 'wb_listora_term_archive_filters', '__return_empty_array' );`
- **Expect**: term URLs fall back to the theme archive (this is the documented opt-out); remove the mu-plugin and step 1 passes again.

### 8. Layout (390)
- **Expect**: no horizontal page scroll; breadcrumb wraps; search bar and card grid stack; tap targets >= 40px; dark mode colours come from tokens (no white breadcrumb box on `body.buddyx-dark-theme`).

## Pass criteria

1. All five taxonomies render the Directory with the term title, breadcrumb, canonical and count.
2. Paging stays on the term URL and a past-the-end page shows the last page.
3. `/listing/` 301s to the Directory; an unknown term 404s while a real one is 200 in the same run.
4. Same output for every role; drafts and pending listings never appear.
5. The filter escape hatch restores the theme archive.

## Fail diagnostics

| Symptom | Likely cause | File |
|---|---|---|
| Blog-style archive with "Read More" | `request` filter not routing (no Directory page mapped) | `class-term-archives.php`, `Page_Registry` |
| `<h1>` is "Directory" not the term | theme reads the title outside the loop | `Term_Archives::page_title` / `document_title` |
| Canonical points at `/listings/` | SEO plugin canonical not filtered | `Term_Archives::canonical` (Yoast/RankMath hooks) |
| Count differs from `wp term get ... count` | search index stale | `wp listora reindex` |
