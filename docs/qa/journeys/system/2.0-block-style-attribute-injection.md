# Block spacing, radius and shadow attributes can only produce numbers, known units and colours

Each Listora block prints a per-instance `<style>` from its attributes (`Block_CSS::generate`). Attributes are author-supplied (editor, or saved post content a Contributor can write), so 2.0.0 allow-lists everything: lengths must match `^\d+(\.\d+)?(px|em|rem|%|vw|vh)$` (a bad side drops the whole declaration), units must be one of `px, em, rem, %, vw, vh` (else `px`), shadow offsets are integer-cast, colours must be a valid colour (else the default), the unique id passes `sanitize_html_class`, and the final CSS is stripped of `<` so it cannot close the style tag. Companion to `system/adversarial-block-attributes.md` (which is about 500s, not injection).

## Steps

### 1. Matrix through the block renderer (administrator)
For each row call `GET /wp-json/wp/v2/block-renderer/listora/listing-grid?context=edit` with `attributes[uniqueId]=j20` plus the attributes shown, and read the `<style>` in `rendered`:
| Case | Attributes | Expect in the style |
|---|---|---|
| good length | `padding={top:12,right:8,bottom:12,left:8}`, `paddingUnit=rem` | `padding: 12rem 8rem 12rem 8rem;` (positive control) |
| declaration breakout | `padding.top = "1px;}body{display:none}/*"` (others `1`) | NO padding rule at all; no `body{display:none}` anywhere |
| bad unit | `paddingUnit = "px;}x{"` | falls back to `px`: `padding: 4px 4px 4px 4px;` |
| url() colour | `boxShadow=true`, `shadowColor="url(https://evil.example/x.png)"` | default `rgba(0,0,0,0.12)`; no `url(` in the output |
| tag breakout colour | `boxShadow=true`, `shadowColor="red}</style><script>alert(1)</script>"` | default colour; no `<script>`, no extra `</style>` |
| good colour | `boxShadow=true`, `shadowColor="rgba(10,20,30,0.4)"`, `shadowBlur=12` | `box-shadow: 0px 4px 12px 0px rgba(10,20,30,0.4);` (positive control) |
| unique id | `uniqueId = "a b}</style><script>x"` | class is the sanitised `.listora-block-abstylescriptx` (no spaces, braces, angle brackets) |
- **Expect**: HTTP 200 on every row; `grep -c '<script' ` of every `rendered` string is 0; the outputs above were observed 2026-10-12 with `rest_do_request` as user 1.
- **On fail**: `includes/class-block-css.php` (`css_length` ~143, `color` ~173, `unit` ~131, `render` strip of `<` ~40).

### 2. Saved content a Contributor can write (anonymous reads)
- **Action**: as contributor1 (can create posts, cannot use unfiltered HTML) save a draft page containing `<!-- wp:listora/listing-grid {"uniqueId":"j20b","boxShadow":true,"shadowColor":"red}</style><script>window.__j20=1</script>","padding":{"top":"1px;}body{background:red}/*","right":1,"bottom":1,"left":1}} /-->`; an editor/admin publishes it; open it logged out.
- **Expect**: HTTP 200; `view-source` has no `window.__j20`; no `body{background:red}`; `window.__j20` is undefined in the console; the block still renders its listings.
- **Positive control**: the same page with `{"uniqueId":"j20b","paddingUnit":"rem","padding":{"top":2,"right":2,"bottom":2,"left":2}}` shows `padding: 2rem ...` in the style, so the page really renders the block's CSS.

### 3. Other consumers of the same helper
- **Expect**: all eleven Free blocks print their style through `Block_CSS::render` (checked 2026-10-12: listing-card, -grid, -calendar, -categories, -detail, -featured, -submission, -map, -reviews, -search, user-dashboard); pick two more (listing-featured, listing-categories) and repeat the "declaration breakout" and "tag breakout colour" rows: no output change versus the grid.

## Pass criteria

1. No attribute value can add a CSS rule, load an external URL, or close the style tag.
2. Valid lengths, units and colours still render (positive controls).
3. Hostile saved content renders safely for visitors.

## Fail diagnostics

| Symptom | Likely cause | File |
|---|---|---|
| `body{...}` in output | length allow-list loosened | `Block_CSS::css_length` |
| `<script>` in output | `<` strip removed or a second style writer | `Block_CSS::render`; grep other `<style>` emitters |
| Unit passes through | `unit()` not used for a box attribute | `Block_CSS::generate` box loop |
