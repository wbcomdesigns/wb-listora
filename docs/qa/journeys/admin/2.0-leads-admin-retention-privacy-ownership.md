# Site owner: Listings > Leads, retention, privacy tools, ownership

Leads live in `{prefix}listora_leads`. Site owners read all of them under Listora > Listings > Leads (`admin.php?page=listora-leads`, capability `manage_listora_settings`), decide how long they are kept, answer privacy requests from them, and a lead follows its listing to a new author. Owners-side reading is `customer/2.0-leads-guest-to-owner-inbox.md`.

## Setup

- Insert three leads without the form (so this journey is self-contained):
  ```bash
  wp eval '
  global $wpdb; $t=$wpdb->prefix."listora_leads";
  $l=(int)$wpdb->get_var("SELECT ID FROM {$wpdb->posts} WHERE post_title=\"J20 Owner Published\" AND post_type=\"listora_listing\" LIMIT 1");
  $o=(int)get_post_field("post_author",$l);
  foreach([["J20 New","j20-new@example.com","now"],["J20 Old","j20-old@example.com","-13 months"],["J20 Mid","j20-mid@example.com","-5 months"]] as $r){
    $wpdb->insert($t,["listing_id"=>$l,"owner_id"=>$o,"sender_id"=>0,"name"=>$r[0],"email"=>$r[1],"phone"=>"","message"=>"J20 lead ".$r[0],"created_at"=>gmdate("Y-m-d H:i:s",strtotime($r[2]))]);
  } echo "listing $l owner $o\n";'
  ```
- Set retention to "Until deleted" first (Step 3 depends on a known start).

## Steps

### 1. The screen (administrator, 1440)
- **Action**: `$SITE_URL/wp-admin/admin.php?page=listora-leads&autologin=1`.
- **Expect**: shared page header (`.listora-page-header__title` "Leads", description "Every message visitors sent to listing owners through the contact form. Owners see their own under My Dashboard > Leads.") above the notices area, then the hub tab row `.listora-hub-tabs` with "All Listings" and "Leads" (aria-current on Leads), a "Keep leads for" select (`#listora-leads-retention`) with options "3 months, 6 months, 12 months, 24 months, Until deleted", views All / Last 7 days / Last 30 days / Last 90 days, search "Search names, emails and messages", a "Listing ID or title" filter, and columns Received, From, Listing, Message. Count text reads "<n> leads".
- **Expect**: each row shows the sender name + mailto link + phone, the listing as a link to its edit screen, a clamped message, actions "Reply" and "Delete".

### 2. Filters and the 7-day view
- **Action**: open "Last 7 days"; then search `J20 Old`.
- **Expect**: 7 days shows "J20 New" only; search shows only "J20 Old". Clearing search restores the list.
- **Big-site step (2809 listings, thousands of leads)**: with >= 2 pages of leads the pager shows numbered pages; `&paged=999` shows the last page, not an empty table; sort by Received flips order.

### 3. Retention prunes immediately and says so
- **Action**: Keep leads for = "12 months" then Save.
- **Expect**: redirected back with a success notice "Retention saved. Older leads were removed."; "J20 Old" (13 months) is gone, "J20 Mid" (5 months) and "J20 New" stay. DB: `wb_listora_lead_retention_months` = 12.
- **Action**: choose "3 months", Save.
- **Expect**: "J20 Mid" is gone, "J20 New" stays.
- **Action**: choose "Until deleted", Save; insert one 14-month-old row; trigger the daily cleanup: `wp listora cleanup`.
- **Expect**: the old row is kept (0 = never prune).
- **On fail**: `Leads::prune` (`includes/core/class-leads.php`), `Leads_Page::handle_action`.

### 4. Delete one lead (confirm, then gone for the owner too)
- **Action**: Delete on "J20 New" -> the confirm dialog text is "This lead is deleted for good. The listing owner can no longer see it either." -> confirm.
- **Expect**: notice "Lead deleted."; the row is gone; as the listing owner `/my-listings/?tab=leads` no longer lists it (and shows "No messages yet" when it was the last).
- **Action (second admin tab, concurrency)**: delete the same lead again from a stale tab.
- **Expect**: no fatal; the page reloads with no notice and the list unchanged.

### 5. Privacy: export and erase by email
- **Action**: Tools > Export Personal Data > Add Data Export Request for `j20-guest@example.com` (untick the confirmation email), then "Email data"/"Download Personal Data".
- **Expect**: the export has the group "Listora contact messages" with fields Listing, Name, Phone, Message, Sent.
- **Code-level check** (works without mail): `wp eval 'print_r(\WBListora\Core\Leads::export("j20-guest@example.com"));'` returns the group `wb-listora-leads`; the exporter is registered:
  ```bash
  wp eval 'echo isset(apply_filters("wp_privacy_personal_data_exporters",[])["wb-listora-leads"]) ? "REGISTERED":"MISSING";'
  ```
- **Action**: Tools > Erase Personal Data for the same email, "Erase personal data".
- **Expect**: result lists "Listora contact messages" with items removed >= 1; `SELECT COUNT(*) FROM wp_listora_leads WHERE email='j20-guest@example.com'` = 0.
- **Member sent under another address**: send a lead while signed in as dana_whitfield with a DIFFERENT email in the form; export/erase for dana's ACCOUNT email must include it (the lead row has `sender_id` = dana). This is the 2.0.0 Security fix.

### 6. A lead follows its listing to a new author
- **Action**: Listings list > "J20 Owner Published" > Quick Edit > Author = `dana_whitfield` > Update.
- **Expect**: `SELECT DISTINCT owner_id FROM wp_listora_leads WHERE listing_id=<id>` = dana's ID; `/my-listings/?autologin=dana_whitfield&tab=leads` now has the "Leads" tab with the rows; qa_vendor_01's Leads tab no longer lists them (tab may disappear if they own nothing else).
- **Action**: approve a claim on the listing (Moderation > Claims > Approve) as an alternative to Quick Edit.
- **Expect**: same transfer, and "Reverse approval" returns the leads again.
- **On fail**: `Leads::follow_owner` on `post_updated`; claim transfer in `class-claims-controller.php` (~806).

### 7. Role ladder
| Rung | Action | Expect |
|---|---|---|

## Pass criteria

1. Leads screen renders under the shared header with retention, views, search, listing filter and numbered pages.
2. Saving retention prunes immediately with the exact notice; "Until deleted" never prunes.
3. Delete asks for confirmation, removes the row for the owner too, and tolerates a repeat.
4. Personal data export and erase find leads by email and by account, and erase removes them.
5. Leads follow the new author after Quick Edit or a claim, and nobody else gains access.

## Fail diagnostics

| Symptom | Likely cause | File |
|---|---|---|
| Retention save keeps old rows | `prune()` not called in the handler | `class-leads-page.php::handle_action` |
| Export finds only the typed email | `sender_id` branch removed | `Leads::export` / `sender_id()` |
| Owner column stale after author change | `post_updated` hook not registered (Leads::init not called) | `class-plugin.php`, `class-leads.php::init` |
| Editor can open the screen | menu cap widened | `Admin::register_menus` (Leads item) |
