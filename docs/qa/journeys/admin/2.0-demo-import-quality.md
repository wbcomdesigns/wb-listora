# Demo import: every pack, believable dates and features, no email storm, no usable demo passwords

2.0.0 reworked the demo import so a fresh site looks real: publish dates spread over the last 60 days, each type offered only its own features, no approval email per sample listing, demo accounts with random passwords (and a migration that locks old ones), an Events pack dated from the import day, and Settings > Advanced > Re-run Demo Import runs EVERY pack like the wizard and WP-CLI. Short sentinels: `regression/quick-wins-2026-10.md`, `regression/demo-accounts-not-loginable.md`, `regression/event-demo-pack.md`; background progress mechanics: `admin/demo-import-background-progress.md`.

## Setup

```bash
wp eval 'global $wpdb; foreach(["_listora_demo_content","_listora_demo_user"] as $k) echo $k,": ",$wpdb->get_var($wpdb->prepare("SELECT COUNT(*) FROM {$wpdb->postmeta} WHERE meta_key=%s",$k)),"\n";'   # baseline (expect 0)
wp eval 'global $wpdb; echo $wpdb->get_var("SELECT COALESCE(MAX(id),0) FROM {$wpdb->prefix}listora_email_log");'   # MAIL_BASE
```

## Steps

### 1. The wizard offers every pack (administrator, 1440)
- **Action**: `$SITE_URL/wp-admin/admin.php?page=listora-setup&rerun=1&step=demo&autologin=1`.
- **Expect**: no admin notices on the page; radios `input[name=demo_pack]` for Restaurant Directory, Job Board, Real Estate, Hotel Directory, General Directory, Classifieds, Education, Healthcare, Places & Attractions, Events, and "All packs" (11 radios) with "Events: 8 upcoming concerts, conferences and workshops, dated from the day you import" and "All packs: 100+ listings across all 10 listing types"; "Skip demo content - I will add my own listings"; a "Skip setup" link (absent on the Done step).
- **On fail**: `Setup_Wizard::render_step_demo` (`includes/admin/class-setup-wizard.php` ~860+), `wb_listora_get_demo_packs()` (`includes/import-export/import-helpers.php` ~80, 10 slugs).

### 2. Settings > Advanced > Re-run Demo Import runs all ten packs
- **Action**: `admin.php?page=listora-settings&tab=advanced` > "Re-run Demo Import" (`#listora-demo-import-btn`). If demo content already exists a `listoraConfirm` dialog says "Demo listings already exist. Re-running will add duplicate demo content. Continue?" > Continue.
- **Expect**: status "Demo import queued. Importing in background..."; the progress bar (`#listora-demo-import-progress [role=progressbar]`) advances and "N listings imported" counts up; the run ends with the done state. `GET /listora/v1/import/progress/<run_id>` (or the `wb_listora_demo_import_run` action's `$packs` argument, e.g. logged by a throwaway listener) shows the run's packs = restaurant, hotel, real-estate, job-board, general, classified, education, healthcare, place, event (all ten), not the old subset.
- **On fail**: `Demo_Import_Admin::ajax_run_demo_import` (`class-demo-import-admin.php` ~100: empty `packs` falls back to `wb_listora_get_demo_packs()`).
- **Doc check**: the description under the button says "Queues a background import of the default demo listings." The wording predates "all packs"; record it for the docs owner.

### 3. No approval emails for sample listings
- **Action**: after the import completes:
  ```bash
  wp eval 'global $wpdb; echo $wpdb->get_var("SELECT COUNT(*) FROM {$wpdb->prefix}listora_email_log WHERE id > MAIL_BASE");'
  ```
- **Expect**: 0 new rows of events `listing_approved`, `listing_submitted`, `listing_pending_admin` (the seeder suppresses them with `wb_listora_should_send_notification`). Mailpit (or the Email Log screen) is quiet apart from anything unrelated.
- **Positive control**: approve one real pending listing by hand afterwards: the `listing_approved` email IS logged, so the silence above is the seeder, not a broken mailer.
- **On fail**: `Demo_Seeder` (`demo/class-demo-seeder.php` ~257, ~267).

### 4. Publish dates spread over 60 days
- **Action**:
  ```bash
  wp eval 'global $wpdb; print_r($wpdb->get_row("SELECT MIN(p.post_date) mn, MAX(p.post_date) mx, COUNT(DISTINCT DATE(p.post_date)) days FROM {$wpdb->posts} p JOIN {$wpdb->postmeta} m ON m.post_id=p.ID AND m.meta_key=\"_listora_demo_content\" WHERE p.post_type=\"listora_listing\"", ARRAY_A));'
  ```
- **Expect**: `mn` within 60 days before today, `mx` within the last day or two, `days` >= 30 distinct dates (not one import day). `/listings/?listora_sort=newest` differs from the Featured order; no review `created_at` is earlier than its listing's `post_date_gmt`.
- **Expect**: the "New" badge (Pro, 7-day rule) shows on a minority of cards.

### 5. Each type is offered its own features
- **Action**: Directory > choose type Restaurant > Filters > Features; then type Hotel; then Job.
- **Expect**: Each type's list is different and shorter than the site-wide feature list (compare with the number of terms under Categories > Features); a feature that no listing of that type uses never appears under it. Record the three lists; identical lists across types mean the per-type allowed list is not applied. Counts are the number of listings in that type using the feature, most used first, with "Show all features (N)" for the rest.
- **DB**: `wp term meta get <restaurant type term id> _listora_allowed_features` is a subset, and differs per type.
- **On fail**: `Demo_Seeder::allow_terms` (~417-440), `wb_listora_get_feature_filter_map()`.

### 6. Accounts cannot be signed in to
- **Action**:
  ```bash
  wp eval 'foreach(get_users(["meta_key"=>"_listora_demo_user","fields"=>["ID","user_login","user_pass"]]) as $u) echo $u->user_login,": ", json_encode(wp_check_password("password",$u->user_pass,$u->ID)),"\n";'
  ```
- **Expect**: `false` for every demo account (random 24-character passwords); the real login form with `author1` / `password` says "The password you entered for the username author1 is incorrect." (never signs in).
- **Upgrade case**: `wp_set_password('password', <demo user id>)`, `update_option('wb_listora_db_version','1.9.0')`, load any page: that account no longer accepts `password`; a demo account whose password the owner changed keeps it.

### 7. Events are dated from import day
- **Action**: Events pack imported; `$SITE_URL/listings/?listora_type=event` and the Events Calendar block page.
- **Expect**: 8 events, start dates between today and ~60 days ahead (recurrence end `+60 days`), none in the past; the calendar month view shows them. Re-import tomorrow and the dates move with the import day.

### 8. Education has contact fields (new install)
- **Action**: Listing Types > Education > field groups.
- **Expect**: Provider group has Phone, Email, Website (schema props `provider.telephone`, `provider.email`, `provider.url`). On an UPGRADED site the saved field list is kept (they are not added), so record "new install only".

### 12. Content imported before 1.9.1 is respread and gets authors (bc-10393531373)

- fails_on: 11204e3c (spread step added in 16bbd3b7). Not verified live.
