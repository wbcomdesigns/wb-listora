# Every Listora admin screen has one header, and notices appear below it

2.0.0 renders every Listora screen's title through `wb_listora_render_admin_header()`: a `.listora-page-header` (icon, one `h1.listora-page-header__title`, a description, optional actions) followed by `<hr class="wp-header-end">`, which is the marker WordPress core uses to move admin notices underneath the header. Hub screens also show the tab row `.listora-hub-tabs`. Third-party notices are hidden inside `.wb-listora-admin` so they do not clutter Listora screens; Listora's own notices carry `listora-notice` and stay visible.

## Steps

### 1. One header per screen (administrator, 1440)
For each URL below (all under `$SITE_URL/wp-admin/`):
| Screen | URL | Header title |
|---|---|---|
| Dashboard | `admin.php?page=listora` | Dashboard |
| Listing Types | `admin.php?page=listora-listing-types` | Listing Types |
| Reviews | `admin.php?page=listora-reviews` | Reviews |
| Claims | `admin.php?page=listora-claims` | Claims |
| Leads | `admin.php?page=listora-leads` | Leads |
| Email Log | `admin.php?page=listora-email-log` | Email Log |
| Settings | `admin.php?page=listora-settings` (any `&tab=`) | Settings |
| Pro: Badges / Analytics / Audit Log | `listora-badges`, `listora-analytics`, `listora-audit-log` | Badges / Analytics / Audit Log |
- **Expect** per screen: exactly one `h1` in the page content (`h1.listora-page-header__title`, with a decorative `<i data-lucide>` icon `aria-hidden=true`), one `hr.wp-header-end`, and the header BEFORE the hr; a one-line `p.listora-page-header__desc`; no second title bar above it; the WordPress "Add New" button (if any) does not duplicate the header.
- **Note**: the core list screens (Listings `edit.php?post_type=listora_listing`, Categories/Locations/Features `edit-tags.php?...`) keep WordPress's own `h1`; they carry the hub tab row but not the shared header. Confirm they still have exactly one `h1`.
- **On fail**: `wb_listora_render_admin_header()` (`includes/class-render-helpers.php` ~227); the screen's render method (grep `wb_listora_render_admin_header(`).

### 2. Hub tab row
- **Action**: open Listings (`edit.php?post_type=listora_listing`), then its second tab "Leads"; Moderation (Reviews, Claims, Needs, Moderators with Pro); Listing Types (Listing Types, Badges with Pro); Tools (Audit Log, Email Log, Webhooks with Pro); Categories (Categories, Locations, Features, Service Categories).
- **Expect**: `nav.listora-hub-tabs[aria-label="<hub name>"]`; the active tab has `.is-active` and `aria-current="page"`; a hub with one tab (Dashboard, Settings, Analytics) shows no tab row; the sidebar menu shows ONE item per hub (nine in total) highlighted while any of its tabs is open.
- **On fail**: `Admin_Hubs::render_tabs` / `group_menu` (`includes/admin/class-admin-hubs.php`).

### 3. Notices appear below the header (positive control first)
- **Action**: Listings > Leads: choose retention "6 months", Save.
- **Expect**: after redirect a `div.notice.notice-success.listora-notice.is-dismissible` with "Retention saved. Older leads were removed." is rendered AFTER `hr.wp-header-end` in the visual order (its `getBoundingClientRect().top` is greater than the header's bottom) and above the retention form; it is dismissible (the X button removes it).
- **Action**: Moderation > Reviews: Approve a pending review (or Reject).
- **Expect**: "<n> review approved. It now shows on the listing." below the header; the same for Claims.
- **Negative**: no notice appears above the title or inside the title row.

### 4. Foreign notices are hidden, Listora's are not
- **Action**: add a mu-plugin `add_action( 'admin_notices', function () { echo '<div class="notice notice-warning"><p>J20 third-party notice</p></div>'; } );`
- **Expect**: on `admin.php?page=listora-reviews` the text is in the DOM but `getComputedStyle(...).display === 'none'` (hidden by `.wb-listora-admin .notice:not(.listora-notice)`); on a core screen such as Dashboard > Updates or Posts it is visible (proving the notice code works). The Leads notice from step 3 has `display: block`.
- **Why computed style**: `innerText` still returns the hidden text; see `regression/admin-notices-are-actually-visible.md`.
- **Cleanup**: remove the mu-plugin.

### 5. Setup wizard is quiet and has Skip (administrator)
- **Action**: with the mu-plugin from step 4 present, open `admin.php?page=listora-setup&rerun=1&step=type`, then `step=demo`, then `step=done`.
- **Expect**: no `.notice` elements at all on the wizard (it removes every `admin_notices` action; only its own demo-import warning is put back); a "Skip setup" link on the type, location, maps, pages and demo steps and NO "Skip setup" on the done step; clicking Skip closes the run and lands on Dashboard.

### 6. Narrow viewport (390)
- **Expect**: title row wraps (description under the title, actions under it), no horizontal page scroll, hub tabs scroll or wrap without clipping the active tab, tap targets >= 40px for header action buttons.

### 7. Role ladder
| Rung | Expect |
|---|---|
| administrator | all steps |
| qa_editor (Editor: reviews + claims only) | sees the Moderation hub with Reviews and Claims tabs only (no Needs/Moderators without Pro), the shared header on both; direct URL `admin.php?page=listora-settings` is "Sorry, you are not allowed to access this page."; no Leads/Settings/Listing Types menu items |
| member-owner (Subscriber) | no Listora menu; `admin.php?page=listora-reviews` -> not allowed |

## Pass criteria

1. Every Listora screen has one `h1.listora-page-header__title`, one `hr.wp-header-end` after it, and one description line.
2. Hub tab rows are present for multi-tab hubs with correct active state; the menu shows one item per hub.
3. Success notices render below the header, visible, dismissible.
4. Third-party notices are hidden on Listora screens and the wizard is notice-free with Skip hidden on the last step.

## Fail diagnostics

| Symptom | Likely cause | File |
|---|---|---|
| Two titles | screen prints its own `<h1>` besides the helper | the screen's render method |
| Notice above the header | `hr.wp-header-end` missing or printed before the header | `wb_listora_render_admin_header` |
| Listora notice invisible | missing `listora-notice` class | the notice markup (`regression/admin-notices-are-actually-visible.md`) |
| Third-party notice visible | CSS scope class `.wb-listora-admin` missing on the screen wrapper | the screen's `<div class="wrap wb-listora-admin">` |
