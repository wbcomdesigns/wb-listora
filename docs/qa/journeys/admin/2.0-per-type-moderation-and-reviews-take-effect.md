# A listing type's own Moderation and Reviews choices actually change what happens

From 1.9.1/2.0.0 each listing type offers Moderation (Use the site setting / Manual approval / Auto-approve) and Reviews (Use the site setting / On for this type / Off for this type). Both now take effect on every surface, and existing sites behave as before until a type is changed (stored value `global`). Short sentinel: `regression/per-type-moderation-and-reviews.md`.

## Steps

### 1. Make two scratch types (administrator, 1440)
- **Action**: `$SITE_URL/wp-admin/admin.php?page=listora-listing-types&action=new&autologin=1`. Create type "J20 Auto" (slug `j20-auto`) and "J20 NoReviews" (slug `j20-noreviews`), each Active, with Frontend submission ticked. Leave both Moderation = "Use the site setting" and Reviews = "Use the site setting".
- **Expect**: both appear in the Listing Types table and in Add Listing's type step.
- **Expect (defaults)**: opening each type again shows both selects at "Use the site setting" (`#listora-type-moderation`, `#listora-type-reviews`); REST `GET /listora/v1/listing-types/j20-auto` returns `moderation:"global"`, `reviews:"global"`.

### 2. Moderation: the type's choice beats the site's (baseline: site = manual)
- **Action**: edit `j20-auto`: Moderation = "Auto-approve", **Save Type** (`#listora-type-moderation` value `auto`). Leave `j20-noreviews` on "Use the site setting".
- **Action**: as dana_whitfield submit one listing of each type (Add Listing wizard, or `wp.apiFetch POST /listora/v1/submit {listing_type, title, description, agree_terms:true}`).
- **Expect**: the J20 Auto listing is `publish` immediately and the success state says it is live (the response/DB `post_status` is the check: `wp post get <id> --field=post_status`); the J20 NoReviews listing is `pending` and the success state says it is waiting for review.
- **Positive control**: submit a third listing of a built-in type (e.g. Restaurant) at the same time: `pending`. Only the type that was changed behaves differently.
- **Action**: switch `j20-auto` to "Manual approval" and the SITE setting to Auto-approve.
- **Expect**: `j20-auto` submissions are `pending` again (type beats site); `j20-noreviews` (global) now publishes. Restore the site setting to "Require admin approval".
- **Also**: the guest email-verification path and admin re-verification use the same answer (`wb_listora_listing_moderation()`): a guest listing of `j20-auto` (Auto-approve) publishes after the verification link, one of a manual type goes to pending.
- **DB**: `wp eval 'echo \WBListora\Core\Listing_Type_Registry::instance()->get("j20-auto")->get_moderation();'` returns `auto` / `manual`.
- **On fail**: `Listing_Type::get_moderation` (`includes/core/class-listing-type.php` ~320), `wb_listora_listing_moderation` (`includes/helpers.php` ~838), `Submission_Controller` status decision.

### 3. Reviews off for one type switches every surface off for THAT type
Publish one listing of `j20-noreviews` and one of `j20-auto` (admin can create them in wp-admin). Edit `j20-noreviews` > Reviews = "Off for this type" > Save Type.
- **Expect on the listing page** (anonymous): no `#tab-reviews`, no rating stars in the header, no review summary, no "Write a review"; JSON-LD has no `aggregateRating`.
- **Expect on cards**: the listing's card shows no rating badge; the J20 Auto card still does when it has reviews (positive control).
- **Expect REST**: `GET /listora/v1/listings/<noreviews id>/reviews` -> 403 `listora_reviews_disabled` ("Reviews are currently disabled on this site."); `POST` the same route as a member -> 403 (see `customer/2.0-review-gate-across-routes.md` for edit/vote/report/reply).
- **Expect**: the `j20-auto` listing's Reviews tab and `GET .../reviews` still work (200).
- **Action**: `PUT /listora/v1/listing-types/j20-noreviews {"reviews":"on"}` (or the select -> "On for this type").
- **Expect**: tab and endpoints come back.
- **On fail**: `Listing_Type::is_review_enabled` (~298), `wb_listora_listing_reviews_enabled`, `blocks/listing-detail/render.php` (~156), `templates/blocks/listing-detail/tabs.php` (~703).

### 4. The site switch wins over "On for this type"
- **Action**: Settings > Features > untick "Reviews & Ratings", Save. Set `j20-auto` Reviews = "On for this type".
- **Expect**: no review UI or endpoint anywhere, including `j20-auto` (the select's hint says "Turning reviews off in Settings turns them off for every type"). Re-enable the feature afterwards.

### 5. Partial updates do not reset the other switch (2.0.0 fix)
- **Action**: `PUT /listora/v1/listing-types/j20-auto {"label":"J20 Auto 2"}` as administrator.
- **Expect**: `moderation` and `reviews` keep the values saved in steps 2-3 (not reset to `global`); `PUT {"moderation":"manual"}` leaves `reviews` alone.
- **Also**: saving the built-in Restaurant type in the editor leaves it built in (`is_builtin` true) and keeps its field settings.

### 7. Clean up
Delete the three scratch listings and the two types (Listing Types > Delete moves any listings away first), restore the Settings.

## Pass criteria

1. Default `global` on both selects; behaviour identical to the site setting until changed.
2. A type's Moderation beats the site setting in both directions, and only for that type.
3. Reviews Off removes tab, rating, card badge, JSON-LD and refuses the endpoints for that type only; the site switch overrides "On".
4. Updating one type setting through the API does not reset another.

## Fail diagnostics

| Symptom | Likely cause | File |
|---|---|---|
| Type "Auto-approve" still pending | submission path reads the site setting directly | `class-submission-controller.php`, `class-email-verification.php` |
| Reviews tab still shown | one surface not calling `wb_listora_listing_reviews_enabled` | grep tabs.php / listing-reviews render |
| `reviews` back to `global` after label edit | partial update building defaults | `class-listing-types-controller.php` ~583 |
