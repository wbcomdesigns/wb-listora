# Email Templates editor: every email, its variables, and the branded header/footer around your words

Settings > Notifications (`admin.php?page=listora-settings&tab=notifications`) lists every email, Free and Pro, as one row with an on/off switch, who it goes to, **Edit template** and **Preview**. The editor writes one non-autoloaded option, `wb_listora_email_templates` (event => subject/body). 2.0.0: the legend lists every variable each email can use, and a customised body is wrapped in the same header, "sent by" footer (and preferences link on marketing mail) as the built-in email, so owners cannot lose the branding by editing the words.

## Steps

### 1. The list (administrator, 1440)
- **Action**: open the tab.
- **Expect**: grouped sections "Listings", "Reviews", "Claims", "Account" (plus Pro groups when Pro is active) each a `ul.listora-email-list`; each `li.listora-email-row` has a toggle (screen-reader text `Send "<email name>"`), the name (e.g. "New message from a visitor"), a one-line description, "To: Listing owner" (or Site admin, Reviewer, Claimant ...), buttons "Edit template" and "Preview". "New message from a visitor" reads "Sent to the listing owner when someone uses the contact form. Replying reaches the sender. Every message is also saved under Leads."
- **On fail**: `Settings_Page` notifications render (`class-settings-page.php` ~1255-1310), `Email_Templates_Page::get_event_map` (~130).

### 2. The editor shows every variable (legend)
- **Action**: "Edit template" on "New message from a visitor".
- **Expect**: the row expands (`aria-expanded=true`) to a Subject field (`placeholder "Leave blank to keep the built-in subject"`), a Message textarea (`placeholder "Leave blank to keep the built-in message"`) and the legend "Placeholders (click to copy):" with chips: `{listing_title} {listing_url} {sender_name} {sender_email} {sender_phone} {message} {dashboard_url} {site_name} {site_url}`; clicking a chip copies it.
- **Positive control**: open "Listing approved": its legend differs (listing/author variables), proving the legend is per email and not one global list.

### 3. A custom body keeps the branded shell
- **Action**: Subject `J20 {sender_name} wrote about {listing_title}`; Message `Hi, {sender_name} says: {message} (phone {sender_phone}) {not_a_variable}`; Save Changes.
- **Expect**: the row shows the "Customized" badge; `wp option get wb_listora_email_templates --format=json` holds both strings.
- **Action**: "Preview" (opens `dialog#listora-email-preview` titled with the email name) and then send a real one (customer journey `customer/2.0-leads-guest-to-owner-inbox.md` step 2, or "Send a test email" below).
- **Expect** in the email: subject `J20 J20 Guest wrote about J20 Owner Published` style (variables replaced, plain text); body wrapped in the standard HTML shell: header block with the email's title ("New message from a visitor") and site name, your text in the content cell with the sender's values HTML-escaped, footer line "This email was sent by <site name>." linked to the site; a literal `{not_a_variable}` stays visible (typos are visible, not blanked); `<script>` and event attributes in your message are stripped (`wp_kses_post`); `Reply-To` is still the sender.
- **Expect**: the plain-text part contains no `&quot;` or `&amp;`.
- **On fail**: `Email_Templates_Page::wrap_body` (~160-200), `apply_override`, `templates/emails/parts/header.php` / `footer.php`.

### 4. Test send and preview from the screen
- **Action**: "Send a test email": Email = "New message from a visitor", Send to = your address (defaults to the admin email), "Send test email".
- **Expect**: status "Sent"; a row appears in Tools > Email Log (event `lead_received`) and in the mail catcher with sample details, customised subject/body applied.
- **Expect** a bad address shows an inline error, never a fatal.

### 5. Reset
- **Action**: tick "Go back to the built-in email on save" in the editor, Save Changes.
- **Expect**: the badge disappears; `wb_listora_email_templates` has no `lead_received` key; the next send uses the built-in subject "New message from <name> about <listing>".

### 6. Switch an email off
- **Action**: untick the toggle for "New message from a visitor", Save; send a contact message.
- **Expect**: the lead is saved (Leads) but no email is sent and none is logged; turn it back on.

### 7. Marketing mail keeps its preferences link
- **Action** (Pro mail, if active; else record "not run"): customise a marketing-class email (e.g. a saved-search alert) and trigger it.
- **Expect**: the footer still has "Manage email preferences".

## Pass criteria

1. Every email appears with recipient, toggle, Edit, Preview; the legend is per email and complete.
2. A custom body is wrapped in the branded header/footer; member values are escaped; unknown tokens stay visible.
3. Test send and Preview use the saved template; Reset returns to the built-in email.
4. Only users with `manage_listora_settings` can edit or test.

## Fail diagnostics

| Symptom | Likely cause | File |
|---|---|---|
| Custom body has no header/footer | override returned raw text | `Email_Templates_Page::apply_override` -> `wrap_body` |
| Legend missing a variable the email uses | event map not in step with `Notifications` vars | `get_event_map()` placeholders vs `Notifications::lead_received` |
| Override ignored on REST/cron sends | filters registered only in admin | `Email_Templates_Page::init` (always-loaded, deferred to `init`) |
