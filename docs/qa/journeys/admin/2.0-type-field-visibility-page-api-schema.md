# A field switched off for the listing page disappears from page, cards, API and structured data; "Show in API" only hides it from the API

Each field in Listing Types > <type> has two switches (default on): **Show on listing page** and **Show in API**. The API never shows more than the listing page does. Hidden fields are also dropped from cards, the gallery data and JSON-LD; owners and editors still get every value from the API (they need it to edit). Short sentinel: `regression/api-mirrors-the-page.md`.

## Steps

### 1. Baseline: everything shows
- **Action**: as anonymous open `$SITE_URL/listing/j20-owner-published/`; then
  ```bash
  curl -s "$SITE_URL/wp-json/listora/v1/listings/<id>" | jq '.listora_meta | {phone,email}'
  curl -s "$SITE_URL/listing/j20-owner-published/" | grep -o '"telephone":"[^"]*"\|"email":"[^"]*"'
  ```
- **Expect**: page shows `555-0142` and a `mailto:j20-visible@example.com` link in the contact card; API `listora_meta` has `phone` and `email`; JSON-LD has `"telephone":"555-0142"` and `"email":"j20-visible@example.com"`.

### 2. Switch the field off for the page (administrator, 1440)
- **Action**: `$SITE_URL/wp-admin/admin.php?page=listora-listing-types&edit=restaurant&autologin=1` > open the **Email** field > untick "Show on listing page" > **Save Type**.
- **Expect**: success notice; re-opening the field shows the box unticked and "Show in API" still ticked (the editor saves each switch independently).
- **On fail**: `assets/js/admin/type-editor.js` (~483), `Type_Editor` save handler, `Listing_Type_Registry` persistence.

### 3. Email is gone everywhere the visitor can look
As **anonymous** and as **member-other (dana_whitfield)**:
- **Expect page**: no `mailto:` link and no email text in the contact card; the Phone is still there (positive control).
- **Expect structured data**: no `"email"` key; `"telephone"` still present.
- **Expect API**: `GET /listora/v1/listings/<id>` `.listora_meta` has `phone`, NOT `email`; the same for `GET /listora/v1/listings?fields=...` (full mode `meta`), `GET /listora/v1/search` (`meta`) and `GET /wp/v2/listings/<id>`.
- **Expect cards**: Directory card for the listing shows no email (turn on "Show on Card" for Email first to make this a real test, then turn it off again).
- **Expect contact form**: still works (the owner is emailed): `Contact form` is not a field display.

### 4. Owner and admin still get the value from the API (role ladder)
| Rung | `GET /listora/v1/listings/<id>` `.listora_meta` | Listing page |
|---|---|---|
| anonymous | phone only | no email |
| member-other (dana) | phone only | no email |
| member-owner (qa_vendor_01, cookie + nonce) | phone, email (+ owner-only internals such as plan/expiry) | no email (the owner's own page follows the same display rule) |
| administrator (control) | phone, email, plus internals | no email |
- **Expect**: public responses never include `plan_id`, `expiration_date`, demo/consent state (`curl` anonymous; only owner/admin have them).

### 5. "Show in API" hides only from the API
- **Action**: tick Email's "Show on listing page" again; untick **Phone**'s "Show in API"; Save Type.
- **Expect** (anonymous/dana): the page shows the phone and the email again; JSON-LD still has `telephone`; the API `listora_meta` has `email` but NOT `phone`. Owner/admin API still returns `phone`.
- **Expect**: a field with "Show on listing page" OFF and "Show in API" ON behaves as off for the API too (the API never exceeds the page): repeat step 2 with Phone and confirm it is absent from the API for visitors.

### 6. Field settings are preserved (2.0.0 fixes)
- **Action**: before saving in step 2/5 note on the Email field: Required, Searchable, Filterable, Show on Card, Schema.org property, Placeholder, Help text. After "Save Type", reopen.
- **Expect**: all of them unchanged except the toggled switch; "Show in API" saved (it did not before 2.0.0). Saving a **built-in** type keeps it built in and keeps its Schema.org type: `wp listora listing-types` before and after shows `Built-in = Yes` and an unchanged Schema column (Restaurant stays `Restaurant`; Classified `Product`, Education `Course`, Healthcare `Physician`, Job and Real Estate keep theirs and never fall back to `LocalBusiness`). Check one of Job, Classified, Education, Healthcare, Real Estate as well, since those were the affected types.
- **On fail**: `type-editor.js` (~851: fields the editor has no control for must be carried through), `Listing_Types_Controller` partial update (~583).

### 7. Restore
Re-tick Email "Show on listing page" and Phone "Show in API"; Save Type; confirm step 1 passes again.

### 8. 390px
- **Expect**: the type editor field panel stacks its checkboxes (Required, Searchable, Filterable, Show on Card, Show on listing page, Show in API) one per line or wrapped, no horizontal scroll; the front-end contact card stays intact.

## Pass criteria

1. Show on listing page OFF removes the field from page, cards, JSON-LD and public API; contact form unaffected.
2. Show in API OFF removes it only from the API; owner/editor/admin always see all values in the API.
3. Public API responses carry no plan/expiry/demo/consent internals.
4. Saving a type does not reset field settings it has no control for, and keeps built-ins built in.
