# Listing expiry is off on a free directory, on while a paid add-on sells time, and dated types still end on their date

2.0.0 changes the default: most directories keep listings until someone removes them, so expiry is OFF and "Default expiration" is 0 (lifetime). Expiry switches on by itself while Pro's paid plans are active, and a note on the setting says why. Events and job deadlines always end on their own date (end + 24 h grace). New types default to no expiry in the editor and the REST API. A lifetime listing never shows a countdown or a Renew button.

## PART A: free directory (Pro deactivated)

### A1. The setting and its wording (administrator, 1440)
- **Action**: `$SITE_URL/wp-admin/admin.php?page=listora-settings&tab=general&autologin=1`, section "Listing Lifecycle".
- **Expect**: checkbox "Enable automatic listing expiration" UNTICKED; help text "Off by default: most directories keep listings until they are removed. When on, listings unpublish after their plan, type or default period, with reminder emails 7 days and 1 day before. Events and job deadlines end on their own date either way."; "Default expiration" = 0 days with "Days before a new listing expires. Leave at 0 for lifetime listings (the directory default). Plans (Pro) override this per plan."; NO note about Monetization. `wp eval 'var_dump(wb_listora_expiration_enabled());'` -> `bool(false)`.
- **On fail**: `class-settings-page.php` (~928-970), `wb_listora_expiration_enabled()` (`includes/helpers.php` ~802), defaults in `wb-listora.php` (`enable_expiration` false, `default_expiration` 0).

### A2. A new listing gets no expiry date
- **Action**: publish a Restaurant as qa_vendor_01 (wizard or admin approve of a pending one).
- **Expect**: `wp post meta get <id> _listora_expiration_date` is empty/unset; the listing stays published after `wp eval 'do_action("wb_listora_check_expirations");'`.
- **On fail**: `Status_Manager::set_expiration_on_publish` (`class-status-manager.php` ~487).

### A3. The owner sees no countdown and no Renew
- **Action**: `$SITE_URL/my-listings/?autologin=qa_vendor_01&tab=listings`, 1440 then 390.
- **Expect**: the row has NO "Expires in N days"/"Expires today" text and NO "Renew"/"Renew Now" button; the Overview "Expiring soon" widget is absent; `GET /listora/v1/dashboard/...` listing items carry `expiry: ""`.
- **Positive control**: step B3 shows both once expiry is on, so their absence here is the setting.
- **On fail**: `Status_Manager::listing_expires` / `expiry_timestamp` (~403, ~420), `tab-listings.php` (~158).

### A4. Dated types still end on their date
- **Action**: publish an Event whose `end_date` is yesterday and a Job whose `deadline` is yesterday (admin: set the fields, Publish), then `wp eval 'do_action("wb_listora_check_expirations");'`.
- **Expect**: each becomes `listora_expired` and `_listora_expiration_date` = end/deadline + 24 hours (computed in the site time zone); a listing of a non-dated type published the same minute is untouched.
- **Positive control**: an Event whose end date is in the future stays published, with expiry = end + 24 h.
- **Expect**: NO reminder emails ("Expiration reminder") are queued for any of them while expiry is off (Email Log has no `expiry_reminder`/`listing_expiring` rows).
- **On fail**: `Expiration_Cron::check_expirations` (`class-expiration-cron.php` ~40: `expire_listings( true )` for dated only).

### A5. New types default to no expiry
- **Action**: `admin.php?page=listora-listing-types&action=new` > the sidebar field "Listing expires after (days)" (`#listora-type-expiry`).
- **Expect**: value 0 and the hint "0 = never expires". Create the type; `GET /listora/v1/listing-types/<slug>` has `expiration_days` 0 (and a POST with no value also stores 0).

## PART B: paid add-on active (Pro, Pricing Plans on)

### B1. Expiry turns itself on, and says why
- **Action**: `wp plugin activate wb-listora-pro`; reload Settings > General.
- **Expect**: the checkbox is still unticked (it is the owner's own switch) but under it a note `p.listora-settings__note`: "Expiration is on while Monetization is active, so paid listings run for their plan's duration and can be renewed." `wb_listora_expiration_enabled()` -> true; the reason comes from `wb_listora_expiration_reason` (Pro Pricing_Plans registers it).
- **Positive control**: A1 had no note with Pro off; ticking the box with Pro active hides the note (the setting alone then decides).

### B2. Plan duration applies
- **Action**: publish a listing on a plan with duration 30 days (Monetization > Plans).
- **Expect**: `_listora_expiration_date` = now + 30 days (UTC); a listing with no plan gets the type/default period only when one is set (else lifetime).

### B3. Countdown and Renew appear
- **Action**: dashboard as the owner of that listing.
- **Expect**: "Expires in 30 days" (or exact date) and a "Renew" button on the row, plus the Overview "expiring soon" entry inside the renewal window (`Renewal window` default 7).

### B4. Own switch with Pro off again
- **Action**: deactivate Pro; tick "Enable automatic listing expiration", Default expiration = 30, Save.
- **Expect**: new listings expire in 30 days, reminders go out 7 days and 1 day before (`wb_listora_check_expirations`), the dashboard shows Renew; untick -> back to A2 behaviour for NEW listings (existing dates stay stored but are not acted on: `expiry_timestamp()` returns 0 for non-expiring listings, so no countdown).

## Pass criteria

1. Free directory: setting off, default 0, no expiry date, no reminders, no countdown or Renew.
2. Events and job deadlines expire on end/deadline + 24 h regardless.
3. Pro plans force expiry on and the note names why; durations come from the plan.
4. New types default to 0 in the editor and in REST.
